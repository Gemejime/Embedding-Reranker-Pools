## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Updates**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and OpenAPI 3.1 specifications (`/docs`, `/redoc`, `/api/docs`, `/openapi.json`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is.
2. **Secured Logging**: All logs must be structured JSON. Strictly redact user query text, raw document chunk spans, customer secrets, authorization headers, bearer tokens, and presigned URLs before emission. Include correlation identifiers (`request_id`, `model_name`, `pool_type`, `batch_size`, `latency_ms`).
3. **Hardware & Pool Isolation**: Dedicated NVIDIA L4 or A10G GPUs (24 GB VRAM) separated into distinct pools:
   - **Online Embedding Pool (Pool A)**: Dynamic queue delay $\le 2\text{ ms}$, max batch size $32$.
   - **Online Cross-Encoder Reranker Pool (Pool B)**: Dynamic queue delay $\le 4\text{ ms}$, max batch size $32$.
   - **Batch Ingestion Pool**: Spot node pool, dynamic queue delay $50\text{ ms}$, max batch size $256$.
4. **In-Engine C++ Tokenization**: Tokenization must execute directly inside the Triton engine pipeline via C++ runtimes (`text_tokenizer`), completely eliminating external Python GIL tokenization bottlenecks.
5. **Standardized FP16 TensorRT Serialization**: Standardize purely on FP16 TensorRT engine serialization (`.plan`), avoiding precision degradation risks and quantization maintenance overhead in Phase 1.
6. **Native Queue Backpressure & Deterministic RRF Fallback**: Enforce Triton native queue timeouts (`max_queue_delay_microseconds`). Upstream orchestrator catches queue saturation status codes to trigger immediate, deterministic bypass to un-reranked Reciprocal Rank Fusion (RRF) scores.
7. **Direct-to-Runtime Transport**: Upstream orchestrators connect directly to Triton via gRPC with HTTP/2 keepalive pooling; ingestion workers utilize native batched gRPC with POSIX shared memory (`/dev/shm` 8 GiB emptyDir RAM) mounts. Custom proxy sidecars are eliminated from data-plane paths.
8. **Operational VRAM Ceilings**: Limit aggregate engine allocations per GPU to $\le 20\text{ GiB}$ ($83\%$ of $24\text{ GB}$) to prevent memory fragmentation and CUDA out-of-memory allocations failing during traffic surges.
9. **Code Cleanliness & Type Safety**: All code must pass `ruff check`, `ruff format --check`, and strict `mypy` typechecks.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Ruff linter and formatter: `python -m ruff check --fix .` and `python -m ruff format .`.
2. Run static type analysis: `mypy scripts api test`.
3. Run test suites: `pytest test/integration test/benchmark`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) is updated with all API, schema, model configuration, or storage modifications.
5. Verify Secured Logging rules: ensure no raw queries, chunk texts, or secrets are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
